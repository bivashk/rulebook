# 3. Plain SQL migrations over Alembic

Status: accepted
Date: 2026-08-29

## Context

The supersession schema is the hard part of this project. Its correctness depends
on constraints and indexes that must be read and understood, not generated.

## Decision

Numbered `.sql` files in `migrations/`, applied in filename order by a runner in
`regqa/migrate.py` that records applied versions in a `schema_migrations` table.
One transaction per file.

## Alternatives considered

- **Alembic.** The standard tool. Supports autogeneration, downgrades and
  branching. Rejected for now because autogenerated migrations tend to be applied
  without being read, which is exactly the failure mode to avoid here.

## Consequences

- No autogeneration, no downgrade path, no merge support for parallel branches.
- Every schema change is reviewable as SQL in a pull request.
- If branching or rollback becomes a real need, migrating to Alembic later means
  stamping the current revision, not rewriting history.
